1The scenario

"SnapHost" is a small image-hosting site with a staff-only admin console. The console was built in a hurry, and the person who wrote it trusted the browser a little too much.

You have one machine to go after. Find your way into the app, get a shell, and take over the server.

2Your target

You are given the machine's IP — set it in the Target IP box above. Throughout it is written as <target-ip>. Start by browsing the site and mapping what is there:

nmap -sC -sV <target-ip>

3Your objective

Capture two flags and submit each exact string:

user flaga foothold as a normal user
root flagfull control of the machine

Flags look like FLAG{...}.

✓Check your flags

Found a flag? Paste it in to verify. Answers are stored only as salted hashes, so this page checks your flag without ever revealing it.

4Rules

  • Attack only the <target-ip> you were given.
  • Any tools are allowed — content discovery, a proxy, sqlmap, and so on.
  • Write down how you got in and how you escalated; explaining it matters.

5A nudge

If you get stuck

It's a web app — start at the admin login and ask what the query really does. Once you're in, think about which file types the server will still execute. Then look for a password that opens more than one door.
